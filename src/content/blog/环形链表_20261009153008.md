# 分析：

## 画图演示：

我们可以定义快慢指针，slow走1步，fast走2步，这样如果是环形链表的话它们终会相遇。

举个例子：

![环形链表过程.png](/image/环形链表_20261009153008/环形链表过程.png)

可以看到这个环形链表的fast在走的第二圈就遇到slow了（当然如果环前面的部分够大，环够小，fast可能要在环里转好几圈才会遇到slow），此时就没有fast的事了，我们让head（头结点）和slow再一起走，步骤如下：

![环形链表过程1.png](/image/环形链表_20261009153008/环形链表过程1.png)

此时head和slow相遇，且正好是环的入口，返回slow或head即可。至于为什么可以这样解，请继续往下看.....

* * *

## 证明：

我们把进入环形链表之前的距离定义为L，环的距离定义为C，slow进入环到与fast相遇的距离为X，fast与slow相遇之前走的环数为N。

L+X即slow一共走的步数，L+N*C+X即fast一共走的步数（为什么不是L+C+X?因为快指针不一定只走了一圈，如果环很小，可能会走好几圈）

又因为fast走的步数为slow步数的两倍，即

2（L+X）= L+N*C+X

化简可得L=N*C-X

也就是L=(N-1)*C+C-X

即fast的最后一圈从一开始slow和fast相遇的地方开始走，正好会和从头开始的指针在环的开始处相遇，有点像追击问题。

![环形链表原理.png](/image/环形链表_20261009153008/环形链表原理.png)

# 结果：

具体代码如下：

```c
    typedef struct ListNode SL;
    struct ListNode *detectCycle(struct ListNode *head) 
    {
        SL *slow=head,*fast=head;
        while(fast && fast->next)//如果为假，就代表不是环形链表
        {
            slow=slow->next;
            fast=fast->next->next;
            if(slow==fast)//当慢指针和快指针相遇时，slow和头结点同时开始走，终究会在环的入口相遇
                while(1)
                {
                    if(slow == head)//如果相遇
                        return slow;
                    slow=slow->next;
                    head=head->next;
                }
        }
        return NULL;
    }
```
