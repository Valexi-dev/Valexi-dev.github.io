在实际生产环境，Redis不可能只有单机配置，一旦服务器出现问题，	可能会**导致数据丢失或其他严重问题**

> 在分布式系统中为了**解决单点问题**，通常会**把数据复制多个副本部署到其他服务器**，满足故障恢复和负载均衡等需求。
> Redis 也是如此，它为我们提供了**复制**的功能，实现了相同数据的多个 Redis 副本。复制功能是Redis的基础，哨兵和集群都是在复制的基础上构建的。

---
例如，有两台Redis服务器，可以设置一台为主机（Main），一台为从机（Secondary）。
==主机通过复制机制将数据重写到从机上==
![主从复制](image/Redis主从复制_20261022112236/主从复制.webp)
主机以写操作为主，从机以读操作为主，通过**读写分离**来减轻负担，当主机崩溃时，还可以把从机的数据当作实时备份
若配置了多台从机，还可以通过**轮询的方式进一步减轻压力**

Redis服务器默认都是主节点（Master），要想让它变为某个主节点的从节点，有三种配置方式：
1. 配置文件：`replicaof [主节点IP] [主节点Port]`（Redis启动时）
2. 启动参数：`redis-server --replicaof [主节点IP] [主节点Port]`（Redis 启动时），**重启后失效**
3. 客户端命令：`REPLICAOF [主节点IP] [主节点Port]`（运行期间立即生效），**在重启后会失效**

> 若主节点配置了密码（`requirepass`参数），在从节点的配置文件中需要有`masterauth
> [主节点密码]`参数，才能通过身份验证并建立主从复制关系

# 配置演示（一主多从）
要模拟多台Redis，可以用启动多个redis-server，但是**要配置不同的端口号**
我们将主节点端口为默认6379，而将两个从节点的配置文件（redis.conf）的port改为其他端口
```bash
# 从节点1
# 配置端口号
# Accept connections on the specified port, default is 6379 (IANA #815344).
# If port 0 is specified Redis will not listen on a TCP socket.
port 6380

# 配置pid文件，通过该文件查看该redis的pid
# Note that on modern Linux systems "/run/redis.pid" is more conforming
# and should be used instead.
pidfile /var/run/redis_6380.pid

# 配置日志文件路径
# Specify the log file name. Also the empty string can be used to force
# Redis to log on the standard output. Note that if you use standard
# output for logging but daemonize, logs will be sent to /dev/null
logfile /myredis/log/6380.log

# 配置RDB文件名
# The filename where to dump the DB
dbfilename dump6380.rdb # 加上端口号更好辨认

# 若开启了AOF，需要修改AOF文件名
# - appendonly.aof.1.base.rdb as a base file.
# - appendonly.aof.1.incr.aof, appendonly.aof.2.incr.aof as incremental files.
# - appendonly.aof.manifest as a manifest file.
appendfilename "appendonly6380.aof"

# 配置主节点密码
# If the master is password protected (using the "requirepass" configuration
# directive below) it is possible to tell the replica to authenticate before
# starting the replication synchronization process, otherwise the master will
# refuse the replica request.
#
masterauth [主节点密码]

# 通过配置文件设置replicaof
replicaof 127.0.0.1 6379
```
```bash
# 从节点2
# 配置端口号
# Accept connections on the specified port, default is 6379 (IANA #815344).
# If port 0 is specified Redis will not listen on a TCP socket.
port 6381

...... # 下面与从节点1的配置类似
```
---
配置完成后，依次启动三个redis-server：
```bash
redis-server /myredis/redis.conf # 主节点
redis-server /myredis/redis-replica1.conf # 从节点1
redis-server /myredis/redis-replica2.conf # 从节点2
```
现在三台Redis都在后台运行

> 若该Redis服务在成为从节点之前有自己的数据，在**成为从节点后也会被覆盖**，数据都是主节点的备份

- **主节点宕机重启后，主从关系依然在**；但如果从节点是通过客户端命令或启动参数配置的，重启后主从关系消失
- 主从关系中，**从节点默认为只读模式，不能写入数据**
```bash
# 从节点1
127.0.0.1:6380> set k1 v1
READONLY You can't write against a read only replica.
```
若要修改也可以在配置文件中找到`replica-read-only`参数，改为no即可（修改从节点会造成主从数据不一致，建议线上不要修改）
```bash
# Since Redis 2.6 by default replicas are read-only.
#
# Note: read only replicas are not designed to be exposed to untrusted clients
# on the internet. It's just a protection layer against misuse of the instance.
# Still a read only replica exports by default all the administrative commands
# such as CONFIG, DEBUG, and so forth. To a limited extent you can improve
# security of read only replicas using 'rename-command' to shadow all the
# administrative / dangerous commands.
replica-read-only yes
```
- 从节点启动后，**先进行一次全量复制，后续跟随（写一条跟一条）**
- 如果已有跟随的主节点，也可以通过`REPLICAOF [主节点IP] [主节点Port]`临时变更，跟随其他主节点

若从节点不想与主节点绑定了，可以执行`REPLICAOF NO ONE`，**停止与其他数据库同步，转为主节点**。断开后不会丢去原有数据
但如果主从复制配置是通过redis.conf配置文件生效的，在该从节点重启后，仍然**会恢复从节点**
# 树形拓扑
当主节点的从机变多后，**主节点负载压力会变大**，这时如果将一些从节点转移到另外一个从节点下，就可以**有效减轻主节点负担**
![树形拓扑](image/Redis主从复制_20261022112236/树形拓扑.webp)
也就是说，**从节点也可以当其他节点的主节点**，直接`replicaof`指向ip+port即可

但即使该Redis服务某个节点的主节点，只要它还是某个节点的从节点，就**依然是只读模式**，不能写入

主从节点⼀般部署在不同机器上，**复制时的网络延迟**就成为需要考虑的问题，这一点在**树形拓扑中会更明显**：越往枝叶的节点，网络延迟越大，因为需要等该从节点的主节点先同步
Redis 为我们提供了`repl-disable-tcp-nodelay`参数用于控制是否关闭 TCP_NODELAY ，默认为 no，即开启 tcp- nodelay 功能
```bash
# Disable TCP_NODELAY on the replica socket after SYNC?
#
# If you select "yes" Redis will use a smaller number of TCP packets and
# less bandwidth to send data to replicas. But this can add a delay for
# the data to appear on the replica side, up to 40 milliseconds with
# Linux kernels using a default configuration.
#
# If you select "no" the delay for data to appear on the replica side will
# be reduced but more bandwidth will be used for replication.
#
# By default we optimize for low latency, but in very high traffic conditions
# or when the master and replicas are many hops away, turning this to "yes" may
# be a good idea.
repl-disable-tcp-nodelay no
```
- 当关闭时，主节点产生的命令数据**无论大小都会及时地发送给从节点**，这样主从之间**延迟会变小**，但**增加了网络带宽的消耗**。适用于主从之间的**网络环境良好的场景**，如同机房部署。
- 当开启时，主节点会**合并较小的 TCP 数据包从而节省带宽**。默认发送时间间隔取决于 Linux 的内核，一般默认为 40 毫秒。这种配置节省了带宽但**增大主从之间的延迟**。适用于主从**网络环境复杂的场景**，如跨机房部署。

# 主从复制优缺点
优点：***解决了单点问题***，单个Redis节点可用性不高，性能有限

缺点：
1. 当从节点变多后，**复制数据的延时会越来越明显**
2. 主机挂了, **从机不会升级成主机**. 只能通过人工干预的方式恢复，这就需要引入**哨兵**（Sentinel）来解决
