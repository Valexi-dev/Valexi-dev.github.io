Redis 的主从复制模式可以将主节点的数据改变同步给从节点，这样从节点就可以起到两个作用：
1. **作为主节点的一个备份**，一旦主节点出了故障不可达的情况，从节点可以作为后备“顶”上来，并且保证数据尽量不丢失（主从复制表现为最终一致性）
2. **从节点可以分担主节点上的读压力**，让主节点只承担写请求的处理，将所有的读请求负载均衡到各个从节点上。
![主节点宕机，从节点上位](image/Redis哨兵配置_20261102105513/主节点宕机，从节点上位.webp)

但这其中也存在着两个问题：
1. 主节点发生故障时，**进行主备切换的过程是复杂的**，需要完全的**人工参与**，导致故障恢复时间无法保障。
2. 主节点可以将读压力分散出去，但**写压力/存储压力是无法被分担的**，还是受到单机的限制。

其中<u>第一个问题是高可用问题，即 Redis 哨兵主要解决的问题。</u>第二个问题是属于存储分布式的问题，留给 Redis 集群去解决

Sentinel相当于**监控**，会监控整个Redis系统，若发现主节点宕机，就可以通过**选举算法**让剩余的某个从节点成为新主节点，**当后续旧主节点回来后，会成为从节点**
**哨兵一般不会只有1个**，否则当该哨兵宕机时，就无人值守了。一般会配置**奇数个哨兵**，这是为了在故障转移时的**投票机制**（奇数好投票），后面会详细说
![哨兵+主从复制](image/Redis哨兵配置_20261102105513/哨兵+主从复制.webp)
根据官网介绍，哨兵的作用如下：
1. **主从监控**：监控主从 redis 库运行是否正常
2. **消息通知**：哨兵可以将故障转移的结果发送给客户端
3. **故障转移**：如果 Master 异常，则会进行主从切换，将其中一个 Slave 作为新 Master
4. **配置中心**：客户端通过连接哨兵来获得当前 Redis 服务的主节点地址

---

哨兵节点会定期**监控 Redis 数据节点和其他哨兵节点**。当主节点发生故障时，故障转移流程大致如下：
1. **主节点出现故障**：主从节点之间的复制连接可能中断，从节点无法继续接收主节点的复制数据。
2. **判断主节点是否下线**：某个哨兵节点发现主节点在规定时间内无法正常响应，会将其判定为**主观下线（SDOWN）**。随后，该哨兵节点会向其他哨兵节点询问主节点的状态。当达到配置的 quorum（法定人数）要求后，将主节点判定为**客观下线（ODOWN）**。（主客观下线概念后面会详细介绍）
3. **选举领导者 Sentinel**：需要执行故障转移时，哨兵节点通过投票和授权机制选举领导者。获得足够授权的哨兵节点负责后续的故障转移工作。
4. **执行故障转移**：
	- 从符合条件的从节点中选择一个，将其**提升为新主节点**。
	- 将其他从节点重新配置为新主节点的从节点。
	- 更新主从拓扑信息，并向客户端提供新的主节点信息。
5. **旧主节点恢复**：如果旧主节点之后恢复，哨兵通常会将其重新配置为新主节点的从节点，使其重新同步数据。
![故障转移流程](image/Redis哨兵配置_20261102105513/故障转移流程.webp)
---
哨兵是单独一个服务，它**不存放数据，只监视维护**，因此哨兵的配置文件与Redis的配置文件是完全不一样的，哨兵会读取`sentinel.conf`配置文件：

- **指定哨兵要监控的主节点**：`sentinel monitor <master-name> <ip> <redis-port> <quorum>`
其中`quorum`表示最少有几个哨兵认可**客观下线**，同意故障迁移的法定票数

==为什么要投票式决定主节点宕机？==
网络是不可靠的，存在网络抖动、网络闪断、防火墙限制以及黑客攻击等问题。有时，<u>由于网络拥堵，一个节点可能会错误地认为master节点已失效</u>，所以也需要其他哨兵节点的意见（这也是为什么哨兵节点推荐为奇数个，因为好投票）

---

- 若主节点设置了密码，还需要在sentinel.conf中指定：`sentinel auth-pass <master-name> <password>`

# 启动哨兵
要启动哨兵，要先有一份`sentinel.conf`配置文件：
```bash
bind 0.0.0.0
 # 若是Dokcer，则不允许在后台，否则 Docker 可能认为启动已经结束并退出，导致容器反复重启
daemonize yes 
protected-mode no
 # Sentinel默认端口
port 26379 
 # 日志文件
logfile "/myredis/sentinel26379.log" 
 # pid文件
pidfile /var/run/redis-sentinel26379.pid
 # 工作目录
dir /myredis
 # 指定要监视的主节点，因为本次测试要部署3个Sentinel，所以这里法定票数定为2票
sentinel monitor mymaster 127.0.0.1 6379 2
 # 若主节点设置了密码
sentinel auth-pass mymaster <主节点密码>
```
Redis的默认端口为6379，Sentinel 的默认端口为26379

启动Sentinel可以用`redis-sentinel <sentinel.conf路径>`
# Docker 安装
由于本章需要在一台机器上模拟 3 台 Redis、3 台 Sentinel，这里为了环境隔离，采用Docker部署

下载Docker（这里以RHEL系·AlmaLinux9.8示例）：
```bash
sudo dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo # 添加 Docker 官方 RPM 仓库
sudo dnf install -y \ # 安装 Docker 和 Docker Compose
  docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```
Docker Compose 可以通过一个yaml文件**统一管理**多个 Docker 容器，很适合当前用途

通过`sudo systemctl start docker`启动docker服务

# Docker Compose 配置
## redis
在工作目录新建`compose.yaml`，作为启动服务的配置文件，配置如下：
```bash

services: # 定义应用包含哪些服务
  redis6379: # 服务名称
    image: redis:7.2 # 使用 Redis 7.2 镜像
    container_name: redis6379 # 指定容器名称
    ports: # 映射宿主机端口和容器端口
      - "127.0.0.1:6379:6379"
    volumes: # 用于把数据保存在容器之外，或者把宿主机上的文件、目录挂载到容器内部
      - ./redis6379/redis.conf:/usr/local/etc/redis/redis.conf:ro
# 把./redis6379/redis.conf挂载容器内的/usr/local/etc/redis/redis.conf，ro代表代表只读
      - redis6379-data:/var/lib/redis # 将名为 redis6379-data 的 Docker 命名卷挂载到容器内的 /var/lib/redis 目录 (需要与redis.conf中的 /dir 参数一致)
    command: ["redis-server", "/usr/local/etc/redis/redis.conf"] # 指定容器启动时执行的命令或传递给镜像默认程序的参数
    restart: unless-stopped # 设置容器退出后，Docker 是否以及何时自动重新启动容器 
# unless-stopped表示：除非明确手动停止这个容器，否则 Docker 会在适当情况下自动尝试重新启动它
# 指定该容器加入的网络
	networks:
	  - redis-net

  redis6380:
    image: redis:7.2
    container_name: redis6380
    ports:
      - "127.0.0.1:6380:6379"
    volumes:
      - ./redis6380/redis.conf:/usr/local/etc/redis/redis.conf:ro
      - redis6380-data:/var/lib/redis
    command: ["redis-server", "/usr/local/etc/redis/redis.conf"]
    restart: unless-stopped
    networks:
      - redis-net

  redis6381:
    image: redis:7.2
    container_name: redis6381
    ports:
      - "127.0.0.1:6381:6379"
    volumes:
      - ./redis6381/redis.conf:/usr/local/etc/redis/redis.conf:ro
      - redis6381-data:/var/lib/redis
    command: ["redis-server", "/usr/local/etc/redis/redis.conf"]
    restart: unless-stopped
    networks:
      - redis-net

volumes: # 声明
  redis6379-data:
  redis6380-data:
  redis6381-data:
  
networks: # 指定加入的网络名称，便于后续sentinel的连接
  redis-net:
    name: redis-net
    driver: bridge

```
这份配置文件会启动3个独立的Redis实例，加载`./redis*/redis.conf`文件，可以分别通过6379，6380，6381端口进入

==redis.conf==
1. 需要在redis.conf中将**守护进程模式关闭**(`daemonize no`)。 `daemonize yes`会让 Redis **作为后台进程运行**。但 Docker 需要 Redis 主进程在前台运行；<u>当 Redis 后台化后，容器入口进程可能认为启动已经结束并退出，导致容器反复重启。</u>
2. container_name 是 **Docker Compose 网络内的服务名**，可以充当IP，因此在填`replicaof <ip> <port>`时，要填Docker容器内的ip和port，根据上面配置，即`replicaof redis6379 6379`
3. 在上面的compose.yaml中，两个从节点设置的是由宿主机6380、6381映射容器中的6379，因此在各自的redis.conf中，也要指定`port 6379`
4. 在哨兵模式中，主节点也需要配置`masterauth`参数，在当前 Redis 实例作为从节点时，**用于向主节点进行身份认证**。
5. Docker部署时，日志文件参数填`logfile ""`，Redis 会将日志**输出到stdout和stderr**，Docker 可以捕获这些日志。可以用`docker logs redis6379`等命令查看。
	- 若指定日志文件路径，Redis 会将日志**写入指定文件**，而不是通过标准输出输出常规日志。

## sentinel
哨兵也用docker compose配置管理

为了**确保redis-server启动后再启动redis-sentinel**，这里把sentinel的配置放在另外一个compose.yaml（如果先启动 redis-sentinel 的话, 可能触发额外的选举过程, 混淆视听.）

在工作目录下创建`compose-sentinel.yaml`，配置文件如下：
```bash

services:
  sentinel1:
    image: 'redis:7.2'
    container_name: redis-sentinel26379
    restart: unless-stopped
    command: redis-sentinel /etc/redis/sentinel.conf
    volumes:
      - ./sentinel26379/sentinel.conf:/etc/redis/sentinel.conf
    ports:
      - 26379:26379
 # 指定与redis用同一网络
    networks:
      - redis-net

  sentinel2:
    image: 'redis:7.2'
    container_name: redis-sentinel26380
    restart: unless-stopped
    command: redis-sentinel /etc/redis/sentinel.conf
    volumes:
      - ./sentinel26380/sentinel.conf:/etc/redis/sentinel.conf
    ports:
      - 26380:26379
    networks:
      - redis-net

  sentinel3:
    image: 'redis:7.2'
    container_name: redis-sentinel26381
    restart: unless-stopped
    command: redis-sentinel /etc/redis/sentinel.conf
    volumes:
      - ./sentinel26381/sentinel.conf:/etc/redis/sentinel.conf
    ports:
      - 26381:26379
    networks:
      - redis-net

networks:
  redis-net:
    external: true
    name: redis-net

```
如果要用 Docker 启动 sentinel：
==sentinel.conf==
- 在`sentinel monitor mymaster redis6379 6379 2`之前，配置`sentinel resolve-hostnames yes`，让 Redis Sentinel **启用主机名解析**
- **将守护进程模式关掉**：`daemonize no`，否则当 Sentinel 后台化后，容器入口进程可能认为启动已经结束并退出，导致容器反复重启

---
在启动redis-server之后，再通过`sudo docker compose -f compose-sentinel.yaml up -d`命令启动哨兵（默认选compose.yaml，-f可以指定加载的配置文件）
